Good. Navigation is locked. Now let’s settle the stack properly — because CrewAI, LangGraph, LangChain, and FastAPI are not competitors. They sit on different layers. Mixing them without knowing why is how POCs become messy.

I’ll explain each layer, then FAISS vs others, then a concrete recommendation you can pick from.

1. First: the layers (this is the important mental model)
Think of the app as 5 layers. Each tool belongs to one layer only.

text

┌─────────────────────────────────────────────────────────┐
│  LAYER 1 — UI                                           │
│  Streamlit  (what the candidate sees)                   │
│  Already decided ✅                                      │
├─────────────────────────────────────────────────────────┤
│  LAYER 2 — API / Transport                              │
│  FastAPI  OR  “no API, just Python function calls”      │
│  This is NOT an AI framework                            │
├─────────────────────────────────────────────────────────┤
│  LAYER 3 — Orchestration (who talks to whom)            │
│  CrewAI  /  LangGraph  /  plain LangChain chains        │
│  This is the “brain wiring”                             │
├─────────────────────────────────────────────────────────┤
│  LAYER 4 — Building blocks (RAG, tools, prompts)        │
│  LangChain  (retrievers, embeddings, tools, loaders)    │
│  Used UNDER CrewAI or LangGraph                         │
├─────────────────────────────────────────────────────────┤
│  LAYER 5 — Models + Memory                              │
│  LLMs: OpenAI / Gemini (switchable)                     │
│  Vectors: FAISS / Chroma / Pinecone                     │
│  Structured data: SQLite                                │
└─────────────────────────────────────────────────────────┘
So the question is not “LangChain or FastAPI or LangGraph?”

The real questions are:

Do we need an HTTP API? → FastAPI yes/no
How do agents work together? → CrewAI or LangGraph
How do we do RAG / tools / embeddings? → LangChain (almost always, even with CrewAI)
Where do embeddings live? → FAISS / Chroma / etc.
2. FastAPI — do we actually need it?
What it is: a Python web server. You expose endpoints like POST /chat, GET /profile. Other apps (mobile, React, another service) call them.

What it is NOT: an AI framework. It does not do agents, RAG, or LLM calls by itself.

FastAPI	No FastAPI (Streamlit calls Python directly)
Extra process to run	Yes (uvicorn)	No — one streamlit run
Good for mobile / 2nd UI later	Yes	No
Extra code	Routes, schemas, CORS, auth	Almost none
Debugging	Harder (UI + API + agents)	Easier
Fits this POC	Only if you want a “real backend”	Best for POC
Need for this project right now: No.
Streamlit and CrewAI live in the same Python process. Dashboard → Python function → Crew → LLM. No HTTP in the middle.

When you WOULD add FastAPI later:

a mobile app
a separate React frontend
exam-delivery as its own service
multiple teams consuming the same APIs
Decision: skip FastAPI for the POC. If you want, we design the Python modules so they can be wrapped in FastAPI later without rewrite (services/ folder, no Streamlit imports inside business logic).

3. LangChain vs LangGraph vs CrewAI
These three get mixed up constantly. Here’s the clean version.

LangChain — the toolbox
What it is: Lego pieces for LLM apps.

Load PDFs / markdown
Split text into chunks
Create embeddings
Store/search in FAISS
Prompt templates
Tools (search, calculator, DB query)
Output parsers (force JSON)
What it is NOT: a good multi-agent system. Old “Chains” are linear: A → B → C. Bad at “if eligibility fails, go to KYC; if pass, generate study plan.”

Pros	Cons
Industry standard for RAG	Easy to write spaghetti
